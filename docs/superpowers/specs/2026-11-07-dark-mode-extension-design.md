# Расширение тёмного режима для Chrome — дизайн

- **Дата:** 2026-11-07
- **Статус:** черновик на ревью
- **Рабочее название:** DarkExt (финальное имя — до публикации в Store)

## 1. Цель и рамки

Расширение для Chrome (и других Chromium-браузеров), которое автоматически включает тёмный режим на сайтах и даёт пользователю гибко подогнать цвета под себя.

**Аудитория и этапы.** Сначала — для личного использования (установка «Загрузить распакованное»), затем публикация в Chrome Web Store. Архитектура с первого дня рассчитана на публикацию: Manifest V3, без сетевых запросов к внешним серверам, без телеметрии, интерфейс RU + EN.

### 1.1 Что входит в MVP

1. Два режима затемнения:
   - **«Адаптивный»** (по умолчанию) — перекраска каждого цвета страницы с сохранением оттенка.
   - **«Свой стиль»** — замена исходных цветов цветами шаблона стиля по ролям, без порчи иерархии сайта.
2. Три уровня настройки:
   - ползунки (яркость, контраст, сепия, оттенки серого, приглушение изображений) и готовые стили;
   - собственные стили (шаблон из 14 цветов);
   - выбор элемента на странице и назначение ему цветов без написания CSS.
3. Глобальное поведение «вкл везде, кроме…» или «выкл везде, кроме…» + переопределение любых настроек на уровне сайта.
4. Автоопределение сайтов, у которых уже есть тёмная тема, — такие сайты не трогаются (с ручным переопределением).
5. Следование системной теме (`prefers-color-scheme`).
6. Горячие клавиши.
7. Синхронизация настроек через `chrome.storage.sync`.
8. Импорт/экспорт всех настроек в JSON.
9. Локализация RU + EN через `chrome.i18n`.

### 1.2 Вне рамок MVP

- расписание включения по времени;
- ручной CSS-редактор;
- режим «фильтр/инверсия»;
- настройки на домен с поддоменами (`*.google.com`);
- выбор элемента внутри iframe;
- закрытые (closed) shadow root;
- Firefox и другие не-Chromium браузеры.

### 1.3 Критерии успеха

- На типичных светлых сайтах (Википедия, GitHub в светлой теме, Stack Overflow, новостные сайты, Gmail) страница становится тёмной, читаемой, с узнаваемым дизайном (режим «Адаптивный»).
- В режиме «Свой стиль» страница выглядит в цветах выбранного стиля, а карточки, меню, кнопки и плашки ошибок/успеха остаются различимыми.
- Сайты с собственной тёмной темой не изменяются.
- При поведении «выключено везде» нет тёмной вспышки на невыбранных сайтах; на выбранных нет белой вспышки при загрузке.
- Любое изменение в popup видно на странице сразу, без перезагрузки.

## 2. Технологии

- TypeScript (strict), Vite, React 18 для popup и страницы настроек.
- Content scripts собираются как IIFE (без ES-модулей) — конкретный способ сборки (CRXJS или multi-entry Vite) выбирается в плане реализации.
- `zod` — валидация импорта и схемы настроек.
- Vitest + jsdom — модульные тесты; React Testing Library — компонентные; Playwright (Chromium с загруженным расширением) — сквозные.
- Без внешних CDN и сетевых запросов, кроме загрузки CSS-файлов самих посещаемых сайтов.

### 2.1 Разрешения манифеста

| Разрешение | Зачем |
|---|---|
| `storage` | настройки (`sync` + `local`) |
| `scripting` | динамическая регистрация скрипта-заглушки (`registerContentScripts`) |
| `host_permissions: <all_urls>` | content scripts на всех сайтах; загрузка кросс-доменных CSS из фонового скрипта |
| `commands` (ключ манифеста) | горячие клавиши |

Разрешение `tabs` не требуется: при host permission `<all_urls>` поле `url` вкладки доступно и в `sender.tab.url` (для сообщений от content script), и в результатах `chrome.tabs.query` (для popup).

## 3. Архитектура

```
┌──────────────────────── Service worker (background) ────────────────────────┐
│ storage (sync/local, квоты, debounce) · resolver · registration (заглушка)   │
│ css-fetch (кросс-доменные CSS, кэш сессии) · commands · messaging hub · badge│
└───────────────▲──────────────────────────▲──────────────────────────▲───────┘
                │ сообщения                │                          │
   ┌────────────┴────────────┐   ┌─────────┴─────────┐     ┌──────────┴─────────┐
   │ Content script (каждый   │   │ Popup (React)     │     │ Options (React)    │
   │ фрейм, document_start)   │   └───────────────────┘     └────────────────────┘
   │ loader · detector ·      │
   │ pipeline(ColorMapper) ·  │◄── main-world hook (shadow DOM, adoptedStyleSheets)
   │ overrides · picker       │
   └──────────────────────────┘
                ▲ все чистые функции
   ┌────────────┴─────────────────────────────────────────────────────────────┐
   │ src/core: color · mapping (Adaptive/Style) · settings (schema, resolve,  │
   │ migrate, quota, presets) · selector · css (base rules, mirror) · io      │
   └──────────────────────────────────────────────────────────────────────────┘
```

### 3.1 Компоненты

**Service worker (`src/background`)**
- `storage` — единственная точка чтения/записи хранилища; объединяет `sync` и `local`; оценивает размер записей и переносит не помещающиеся в `local` (§4.4); debounce записей ~500 мс.
- `resolver` (обёртка над чистой функцией ядра) — собирает итоговую конфигурацию по URL вкладки.
- `registration` — поддерживает зарегистрированный скрипт-заглушку для нужного набора сайтов (§5.2).
- `css-fetch` — загружает текст кросс-доменных таблиц стилей, кэширует на время сессии (`chrome.storage.session` или память).
- `commands` — обработка горячих клавиш.
- `messaging` — хаб сообщений между popup/options и вкладками; рассылает `CONFIG_CHANGED`.
- `badge` — статус на иконке (вкл/выкл/уже тёмный/ошибка).

**Content script (`src/content`)** — `document_start`, `all_frames: true`, `match_about_blank: true`.
- `loader` — запрашивает итоговую конфигурацию, запускает конвейер.
- `detector` — определяет, тёмная ли страница сама по себе (§5.3).
- `pipeline` — единый конвейер: сбор цветов → сопоставление через `ColorMapper` → запись зеркальных стилей → наблюдатель (§6).
- `overrides` — слой правок элементов поверх конвейера (§8).
- `picker` — режим выбора элемента и панель правки, UI в shadow root (§8).

**Main-world hook (`src/main-world`)** — content script с `world: "MAIN"`; перехватывает `attachShadow` и изменения `adoptedStyleSheets`, сообщает о них изолированному content script через `CustomEvent`/`postMessage`.

**Popup и Options (`src/ui`)** — React; общие компоненты в `src/ui/shared` (выбор цвета, ползунок, образец стиля, `t()` для i18n).

**Ядро (`src/core`)** — чистые функции без доступа к `chrome.*` и (кроме `selector`) к DOM:

| Модуль | Ответственность |
|---|---|
| `color` | разбор CSS-цветов, OKLCH ↔ sRGB, контраст WCAG |
| `mapping/adaptive` | `AdaptiveMapper` |
| `mapping/style` | `StyleMapper` + анализ страницы |
| `settings/schema` | типы и zod-схемы, версия схемы |
| `settings/defaults`, `settings/presets` | умолчания и 5 встроенных стилей |
| `settings/resolve` | глобальные + сайт → итоговая конфигурация; решение «затемнять или нет» |
| `settings/migrate` | цепочка миграций по версиям |
| `settings/quota` | оценка размера записей, решение sync/local |
| `selector` | генерация устойчивого CSS-селектора (работает с DOM, тестируется в jsdom) |
| `css` | базовые правила, построение зеркального правила из исходного |
| `io` | экспорт/импорт, валидация, слияние |

### 3.2 Интерфейс стратегии сопоставления

```ts
type Role = 'bg' | 'text' | 'border' | 'shadow';

interface RuleContext {
  selector: string;          // селектор исходного правила ('' для inline)
  isLink: boolean;           // правило/элемент относится к <a>
  pairedBg?: Color;          // фон, заданный в том же правиле (для проверки контраста)
}

interface ColorMapper {
  prepare(stats: PageColorStats): void;          // AdaptiveMapper — no-op
  map(color: Color, role: Role, ctx: RuleContext): string; // CSS-значение
}
```

Пост-обработка ползунков (яркость, контраст, сепия, оттенки серого) применяется к результату `map` одинаково для обеих стратегий. Результаты мемоизируются по ключу `(color, role, флаги ctx)`.

### 3.3 Протокол сообщений

| Направление | Тип | Данные → ответ |
|---|---|---|
| content → bg | `GET_CONFIG` | — → `EffectiveConfig` (по URL вкладки, не фрейма) |
| content → bg | `FETCH_CSS` | `{url}` → `{text}` \| `{error}` |
| content → bg | `REPORT_STATE` | `{status, detectedDark, overridesMissing, error?}` |
| popup/options → bg | `GET_TAB_STATE` | `{tabId}` → состояние вкладки |
| popup/options → bg | `UPDATE_GLOBAL` / `UPDATE_SITE` / `UPDATE_STYLES` | частичный патч → ok \| ошибка квоты |
| popup → bg | `PREVIEW` | временная конфигурация → пересылается во вкладку без записи |
| popup → bg | `START_PICKER` | `{tabId}` |
| bg → content | `CONFIG_CHANGED` | `EffectiveConfig` |
| bg → content | `START_PICKER` | — |

Все типы сообщений описаны в одном модуле `src/shared/messages.ts` как размеченное объединение (discriminated union).

## 4. Модель данных и хранение

### 4.1 Шаблон стиля (общий для обоих режимов)

14 цветов, хранятся как hex `#rrggbb`:

| Группа | Ключи |
|---|---|
| Фоны | `bg` (фон страницы), `surface` (карточки, панели), `elevated` (меню, модальные окна, кнопки) |
| Текст | `text`, `textMuted`, `onAccent` (текст на акцентном фоне) |
| Ссылки | `link`, `linkVisited` |
| Рамки | `border` |
| Акценты | `accent`, `success`, `warning`, `danger` |
| Прочее | `selection` |

Состояния hover/active вычисляются сдвигом светлоты в OKLCH (±0.05), не хранятся.

«Адаптивный» режим использует `bg`, `surface`, `text`, `textMuted`, `link`, `border`, `selection`; «Свой стиль» — все 14.

### 4.2 Встроенные стили (в коде, не в хранилище)

| id | Название | Идея |
|---|---|---|
| `graphite` | Графит (по умолчанию) | нейтральный тёмно-серый, мягкий контраст |
| `midnight` | Глубокая ночь | синеватый тёмный |
| `oled` | OLED | `bg` = `#000000` |
| `warm` | Тёплый | коричневатый фон, кремовый текст |
| `contrast` | Высокий контраст | чёрный/белый, яркие акценты, контраст текста ≥ 7 |

Встроенные стили только читаются; «Дублировать» создаёт пользовательскую копию.

### 4.3 Записи в `chrome.storage.sync`

```ts
// ключ 'g'
interface GlobalSettings {
  v: number;                       // версия схемы
  def: 'on' | 'off';               // поведение по умолчанию
  sys: boolean;                    // следовать системной теме
  eng: 'adaptive' | 'style';       // режим по умолчанию
  st: string;                      // id стиля по умолчанию
  adj: Adjustments;
  keepBgImages: boolean;           // «Свой стиль»: сохранять фоновые изображения
}

interface Adjustments {            // все в процентах
  br: number;   // яркость, 50..150, по умолчанию 100
  ct: number;   // контраст, 50..150, 100
  sp: number;   // сепия, 0..100, 0
  gs: number;   // оттенки серого, 0..100, 0
  img: number;  // приглушить изображения, 0..30, 0
}

// ключ 'styles' — пользовательские стили
type UserStyles = Array<{ id: string; name: string; c: StyleColors }>;

// ключ 's:<host>' — только отличия от глобальных
interface SiteSettings {
  on?: boolean;                    // принудительно вкл/выкл
  eng?: 'adaptive' | 'style';
  st?: string;
  adj?: Partial<Adjustments>;
  det?: true;                      // затемнять, даже если сайт уже тёмный
  r?: OverrideRule[];
}

// [селектор, фон, текст, рамка, флаги]; значение — '#hex' | '@<ключ стиля>' | null
type OverrideRule = [string, string | null, string | null, string | null, number];
// флаги: bit0 — текст во вложенных элементах, bit1 — «ко всем похожим»
```

**Ключ сайта** — `hostname` в нижнем регистре без ведущего `www.`. Поддомены различаются.

### 4.4 Квоты и запись

Лимиты `sync`: 100 КБ всего, 8 КБ на запись, 512 записей, 120 записей/мин, 1800 записей/час.

- Изменения из popup (ползунки, выбор цвета) сначала идут на страницу как `PREVIEW`, без записи. Сохранение — через ~500 мс после последнего изменения.
- Перед записью `core/settings/quota` оценивает размер (JSON-длина ключа + значения). Если запись сайта не помещается (в 8 КБ или в общий остаток), она пишется в `chrome.storage.local` под тем же ключом и с пометкой; из `sync` удаляется. UI показывает «только на этом устройстве» и предлагает почистить старые сайты.
- Чтение объединяет `sync` и `local`. Ключ сайта в норме живёт только в одном хранилище (при переносе: запись в `local`, затем удаление из `sync`). Если ключ есть в обоих (например, другое устройство записало его в `sync`), на этом устройстве побеждает `local`; при следующей записи этого сайта делается попытка вернуть его в `sync`.
- Ошибка лимита частоты записей → повтор с экспоненциальной паузой (1 с, 2 с, 4 с, максимум 5 попыток), затем ошибка в UI.

### 4.5 Миграции

`g.v` — версия схемы. При старте service worker `core/settings/migrate` прогоняет миграции от текущей версии до последней. При сбое миграции исходные данные сохраняются в `local` под ключом `backup:<v>`, настройки сбрасываются на умолчания, пользователь видит уведомление со ссылкой на скачивание копии.

### 4.6 Импорт/экспорт

Формат файла:

```json
{ "format": "darkext-settings", "version": 1,
  "global": { … }, "styles": [ … ], "sites": { "<host>": { … } } }
```

- В экспорт попадают записи из `sync` и `local`.
- Импорт: валидация zod целиком → при ошибке показывается путь и причина (`styles[2].c.bg: не цвет`), данные не меняются. После валидации пользователь выбирает **«Заменить всё»** или **«Объединить»** (при совпадении ключей побеждает импорт). Перед записью — миграция по версии файла.

## 5. Применение темы

### 5.1 Решение «затемнять или нет»

Чистая функция `shouldApply(global, site, env)`; правила по порядку:

1. `site.on === false` → не применять.
2. `enabled = site.on ?? (global.def === 'on')`; если `!enabled` → не применять.
3. `global.sys && !env.systemDark` → не применять. Смена системной темы отслеживается через `matchMedia('(prefers-color-scheme: dark)')` и переоценивается на лету.
4. `env.pageIsDark && !site.det` → не применять, статус «уже тёмный».
5. Иначе — применять.

Шаг 4 выполняется после работы детектора; до этого действует только заглушка.

Конфигурация определяется по URL **вкладки** (iframe получает настройки сайта верхнего уровня).

### 5.2 Без вспышек: динамическая заглушка

Service worker регистрирует через `chrome.scripting.registerContentScripts` маленький **JS**-скрипт-заглушку (`runAt: document_start`, `allFrames: false`):

- при `def: 'on'` — `matches: <all_urls>`, `excludeMatches` — сайты с `on: false`;
- при `def: 'off'` — `matches` — только сайты с `on: true`.

Заглушка синхронно добавляет в `documentElement` элемент `<style data-darkext="placeholder">` с фиксированным нейтральным тёмным фоном и светлым текстом (`#1e1e1e` / `#e0e0e0`). Её задача — только убрать белую вспышку; точные цвета через несколько миллисекунд применяет основной конвейер, после чего заглушка удаляется.

- Файлов два: `placeholder.js` и `placeholder-sys.js` (стиль обёрнут в `@media (prefers-color-scheme: dark)`); регистрируется тот, что соответствует `sys`. Зарегистрированные скрипты статичны, поэтому цвета в заглушке фиксированы.
- Заглушка — именно JS-вставка `<style>`, а не регистрация CSS-файла: CSS, внедрённый расширением, нельзя отключить из content script, и детектор (§5.3) видел бы наш тёмный фон вместо фона сайта.
- Регистрация обновляется при любом изменении `def`, `sys` и поля `on` сайтов.

### 5.3 Детектор тёмной страницы

Запускается после `DOMContentLoaded` и повторно после `load`, если первый результат неуверенный.

1. Наши стили временно отключаются (`media="not all"`), чтение и возврат выполняются синхронно в одной задаче — без перерисовки.
2. Признаки:
   - вычисленный `color-scheme` у `:root` содержит только `dark`, либо `meta[name=color-scheme]` = `dark` / `light dark` при тёмной системной теме;
   - средняя светлота OKLCH фона в 9 точках сетки экрана (`document.elementsFromPoint`, первый непрозрачный фон по стеку; при отсутствии — фон `body`/`html`, затем белый).
3. Страница тёмная, если средняя светлота `L < 0.4`. Признак `color-scheme` без подтверждения по светлоте не достаточен.
4. Если тёмная и `!site.det` — конвейер снимается вместе с заглушкой, статус `detectedDark` отправляется в service worker.

### 5.4 Порядок загрузки страницы

1. Заглушка (если зарегистрирована) → тёмный фон.
2. Content script → `GET_CONFIG`.
3. Если применять — запуск конвейера с нужным `ColorMapper`, затем слой правок.
4. `DOMContentLoaded` → детектор → при необходимости снятие.

### 5.5 Изменения на лету

Изменение в хранилище → service worker пересчитывает конфигурации, обновляет регистрацию заглушки, рассылает `CONFIG_CHANGED` во все вкладки → `pipeline.update(config)` без перезагрузки. `PREVIEW` действует так же, но без записи.

### 5.6 Горячие клавиши (`chrome.commands`)

| Команда | По умолчанию | Действие |
|---|---|---|
| `toggle-site` | `Alt+Shift+D` | вкл/выкл на текущем сайте |
| `toggle-global` | `Alt+Shift+G` | переключить `def` on/off |
| `toggle-mode` | `Alt+Shift+M` | «Адаптивный» ↔ «Свой стиль» на текущем сайте |
| `start-picker` | `Alt+Shift+E` | запустить выбор элемента |

Переназначаются пользователем в `chrome://extensions/shortcuts`.

### 5.7 Недоступные страницы

`chrome://`, `chrome-extension://`, Chrome Web Store, встроенный просмотрщик PDF: popup показывает «На этой странице недоступно», элементы управления сайтом скрыты.

## 6. Конвейер затемнения

### 6.1 Источники цветов

| Источник | Обработка |
|---|---|
| `document.styleSheets` (same-origin) | обход `cssRules` (включая `@media`, `@supports`, `@layer`); для каждого правила с цветами строится зеркальное правило с тем же селектором и сопоставленными значениями (и `!important`, если было в оригинале). Зеркальный лист вставляется сразу после исходного, чтобы сохранить каскад |
| Кросс-доменные листы | `cssRules` недоступны → `FETCH_CSS` → текст разбирается через `new CSSStyleSheet().replaceSync()` → как выше. `@import` внутри разрешаются относительно URL листа |
| CSS-переменные | для каждой `--var` с цветовым значением собирается статистика ролей по свойствам, где она используется через `var()`. Переменная перекрашивается по преобладающей роли (при равенстве — `bg`). Известное ограничение |
| Атрибут `style` | значения меняются через `element.style.setProperty`, оригиналы хранятся в `WeakMap` для отката |
| `adoptedStyleSheets` документа и открытые shadow root | сигналы от main-world hook; в shadow root добавляется собственный зеркальный лист через `adoptedStyleSheets` |
| Умолчания браузера | базовые правила (§6.4) |

**Свойства и роли:**

| Роль | Свойства |
|---|---|
| `bg` | `background-color`, цвета в `background-image` градиентах, `background` (shorthand) |
| `text` | `color`, `fill`, `stroke` (SVG), `caret-color`, `text-decoration-color`, `-webkit-text-fill-color` |
| `border` | `border-*-color`, `border` (shorthand), `outline-color`, `column-rule-color` |
| `shadow` | цвета в `box-shadow`, `text-shadow` |

`background-image: url(...)` не трогается.

### 6.2 Стратегия «Адаптивный» (`AdaptiveMapper`)

В OKLCH (`L` — светлота 0..1, `C` — насыщенность, `h` — оттенок):

- **`bg`:** если `L_in > 0.5` — `L_out` линейно отображается из `[0.5 … 1.0]` в `[L(surface) + 0.06 … L(bg)]` (чем белее, тем ближе к `bg`). Если `L_in ≤ 0.5` — цвет остаётся тёмным, `L_out = min(L_in, L(surface) + 0.10)`.
- **`text`:** если `L_in < 0.5` — `L_out` из `[0 … 0.5]` в `[L(text) … L(textMuted)]` (чем чернее, тем ближе к `text`). Если `L_in ≥ 0.5` — `L_out = max(L_in, L(textMuted))`.
- **`border`:** как `bg`, затем смешивание 50/50 по `L` с `L(border)`.
- **`shadow`:** `L_out = L_in × 0.3`, альфа × 0.6.
- **Оттенок и насыщенность** сохраняются; для `bg` насыщенность ограничивается `C ≤ 0.12`, чтобы крупные цветные плашки не «кричали».
- **Нейтральные цвета** (`C < 0.02`) получают `h` и `C` соответствующего цвета стиля (`bg`/`text`/`border`) — тонировка стиля ощущается по всему сайту.
- **Ссылки:** если `ctx.isLink` и исходный цвет — умолчание браузера (`#0000ee`, `#551a8b`) или нейтральный, используется `link`/`linkVisited`.
- Альфа-канал сохраняется.

Константы (0.06, 0.10, 0.12, 0.3, 0.6) — стартовые значения, подбираются в ходе реализации на фикстурах; инварианты (монотонность, сохранение оттенка) закреплены тестами.

### 6.3 Стратегия «Свой стиль» (`StyleMapper`)

**Проход 1 — анализ (`prepare`).** Собирается `PageColorStats`: все цвета с ролями и частотой (число правил/элементов).

Карта «исходный цвет → ключ стиля»:

- **Нейтральные фоны** (`C < 0.04`): базовый фон = фон `body` (иначе `html`, иначе белый) → `bg`. Остальные сортируются по `ΔL` от базового: ближайшая треть уровней → `surface`, дальше → `elevated`. Уровни определяются кластеризацией по `L` с шагом 0.03.
- **Цветные фоны** (`C ≥ 0.04`) группируются по оттенку `h`:
  - 0–35° и 330–360° → `danger`;
  - 35–100° → `warning`;
  - 100–170° → `success`;
  - остальные → `accent`.
- **Текст:** нейтральные — самый контрастный к базовому фону → `text`, остальные нейтральные с меньшим контрастом → `textMuted`. Цветной текст: при `ctx.isLink` → `link` (`linkVisited` для `:visited`), иначе по той же группировке оттенков.
- **Рамки:** нейтральные → `border`; цветные → `accent` (или группа оттенка).
- **Тени:** `rgba(0,0,0,α×0.6)`.
- **Градиенты:** каждая точка сопоставляется по правилам `bg`; если все точки попали в один ключ — градиент заменяется сплошной заливкой.

**Проход 2 — защита контраста.** Если в правиле заданы и фон, и текст (`ctx.pairedBg`), считается контраст WCAG итоговой пары. При контрасте < 4.5 текст заменяется на `onAccent` или `text` — что контрастнее с итоговым фоном.

**Стабильность.** Карта фиксируется для страницы. Новый цвет, появившийся позже, получает ключ ближайшего (по ΔE в OKLCH, в той же роли) уже сопоставленного цвета; при отсутствии — правило из прохода 1 без пересчёта существующих назначений.

**Настройка режима:** `keepBgImages` — при `false` у элементов с `background-image: url()` изображение скрывается и остаётся только фон стиля.

### 6.4 Базовые правила

Генерируются из стиля для обоих режимов (в «Адаптивном» — через `AdaptiveMapper` от белого/чёрного): `html, body` (фон, текст), `input, textarea, select, button`, `pre, code`, `table, th, td`, `hr`, `::selection`, `::placeholder`, полосы прокрутки (`scrollbar-color`), `:focus-visible` (outline `accent`).

### 6.5 Изображения

`img, video, canvas, picture, svg image, [style*="background-image: url"]` не перекрашиваются. При `adj.img > 0`: `filter: brightness(1 - img/100)`.

### 6.6 Наблюдатель и производительность

- `MutationObserver` на `childList` (новые `<style>`/`<link>`, новые элементы с `style`), `attributes: ['style']`, `characterData` для `<style>`.
- Изменения собираются пакетом и обрабатываются раз в `requestAnimationFrame`.
- Первый проход — листы в `<head>` синхронно; остальное порциями через `requestIdleCallback`.
- Бюджет первого прохода ~300 мс / ~50 000 правил; общий бюджет ~3 с; при превышении — оставшееся не обрабатывается, статус «страница слишком тяжёлая».

### 6.7 Пост-обработка ползунков

После `map`: яркость и контраст масштабируют `L` (контраст — относительно `L(bg)`), сепия смешивает с `oklch(0.6 0.05 70)` на `sp%`, оттенки серого умножают `C` на `1 - gs/100`.

## 7. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Исключение в конвейере | полный откат (`detach`: удалить наши листы, восстановить inline-стили), лог `[DarkExt]`, статус «Ошибка на этой странице», кнопки «Перезапустить» / «Попробовать другой режим» |
| Превышен бюджет производительности | применённое остаётся, статус-подсказка в popup |
| Не загрузился/не разобрался кросс-доменный CSS | лист пропускается; битые правила пропускаются поштучно |
| Квота `sync` | перенос в `local` с пометкой (§4.4) |
| Лимит частоты записи | экспоненциальный повтор (§4.4) |
| Service worker спит | сообщение будит его; повтор запроса 1 раз при ошибке соединения |
| «Extension context invalidated» | content script тихо отключает наблюдатели, оставляет страницу как есть |
| Невалидный импорт | сообщение с путём и причиной, данные не меняются |
| Сбой миграции | бэкап `backup:<v>`, сброс, уведомление (§4.5) |

## 8. Выбор элемента и правки

### 8.1 Запуск и режим выбора

- Кнопка «Выбрать элемент» в popup или `Alt+Shift+E`.
- Только верхний документ (не iframe).
- Оверлей в shadow root, прикреплённом к `documentElement`; стили сайта на него не влияют.
- Наведение — рамка и подпись `tag.class · W×H`.
- Клавиши: `↑` — родитель, `↓` — назад к дочернему, `Esc` — отмена, клик — выбор.

### 8.2 Панель правки

Рядом с выбранным элементом. Три свойства — **Фон**, **Текст**, **Рамка**; для каждого: «Не менять» / цвет из стиля (список с образцами) / свой цвет (`<input type=color>` + hex). Переключатели «Текст и во вложенных элементах», «Ко всем похожим» (со счётчиком совпадений). Кнопки «Сохранить», «Отмена», «Удалить правку». Изменения видны сразу (предпросмотр).

### 8.3 Генерация селектора (`core/selector`)

Порядок попыток:

1. `#id`, если id не похож на сгенерированный: нет подстрок из ≥ 4 цифр подряд, не совпадает с шаблонами хэшей (`^[a-z]{0,3}[-_]?[a-z0-9]{5,}$` с цифрами внутри).
2. Устойчивые атрибуты: `[data-testid]`, `[data-test]`, `[aria-label]`, `[name]`, `[role]` (в сочетании с тегом).
3. Классы, исключая сгенерированные: `css-*`, `sc-*`, `jsx-*`, `_` + хэш, классы с ≥ 3 цифрами, CSS-modules вида `name__hash`.
4. Путь `tag:nth-of-type(n)` вверх до 4 уровней, комбинируя с найденными устойчивыми признаками предков.

Проверка: `querySelectorAll` — для «один элемент» должен вернуть ровно выбранный; для «ко всем похожим» — вариант без `id` и `nth`, по классам/атрибутам; число совпадений показывается.

### 8.4 Применение и хранение

- Правки хранятся в `site.r` (§4.3). Значение `@<ключ>` подставляется из активного стиля, поэтому переживает смену стиля.
- Применяются последним листом с `!important` в обоих режимах. Флаг «текст во вложенных» добавляет правило `<sel> *` для `color`.
- Popup показывает «Правки на этом сайте: N» со списком и удалением; правки, селектор которых сейчас не находит элементов, помечены «не найден на странице» (через `REPORT_STATE.overridesMissing`).

## 9. Интерфейс

### 9.1 Popup (~360 px)

1. Шапка: хост, статус («Активно» / «Выключено» / «Сайт уже тёмный» / «Ошибка» / «Недоступно»), переключатель «На этом сайте»: *По умолчанию / Вкл / Выкл*.
2. Плашка «Сайт уже тёмный — не затемняю» + «Всё равно затемнить» (ставит `det`).
3. Переключатель области редактирования: *Глобально | Этот сайт*; в режиме «Этот сайт» — «Сбросить к глобальным».
4. Режим: *Адаптивный | Свой стиль*.
5. Стиль: выпадающий список с образцами + «Изменить» (быстрый редактор основных цветов: `bg`, `surface`, `text`, `link`, `accent`, `border`). Если выбран встроенный стиль, первое изменение создаёт его пользовательскую копию («Графит (копия)») и переключает на неё.
6. Ползунки: яркость, контраст, сепия, оттенки серого, приглушить изображения.
7. «Выбрать элемент» + «Правки на этом сайте: N».
8. Подвал: «Включено везде / Выключено везде», «Все настройки».

### 9.2 Страница настроек

- **Общие:** поведение по умолчанию, следовать системной теме, режим по умолчанию, глобальные ползунки, «Сохранять фоновые изображения» (для «Свой стиль»).
- **Стили:** список (встроенные — только «Дублировать»); редактор 14 цветов по группам; живой пример (карточка, кнопки, ссылки, поле ввода, плашки ошибки/успеха/предупреждения, таблица, код), переключаемый между режимами; предупреждение о контрасте < 4.5 для пар `text/bg`, `text/surface`, `onAccent/accent`, `link/bg`.
- **Сайты:** таблица «сайт · состояние · режим · стиль · правок · только на этом устройстве», поиск, редактирование, удаление.
- **Резервная копия:** экспорт, импорт (выбор «Заменить всё» / «Объединить»), шкала использования `sync` («34 из 100 КБ»).
- **Горячие клавиши:** текущие сочетания (`chrome.commands.getAll`) + кнопка открытия `chrome://extensions/shortcuts`.

### 9.3 Общее

- Интерфейс расширения тёмный, следует системной теме.
- Все строки — через `t(key, ...subs)` поверх `chrome.i18n.getMessage`; `_locales/ru/messages.json`, `_locales/en/messages.json`; `default_locale: "en"`.

## 12. Известные риски

- **CSS-переменные с несколькими ролями** — перекраска по преобладающей роли может ошибаться; смягчение — правки элементов и режим «Свой стиль».
- **Производительность на тяжёлых SPA** — бюджеты и порционная обработка; возможно неполное покрытие.
- **Ревью в Store** — `<all_urls>` требует обоснования в листинге; политика приватности: данные не покидают браузер (кроме синхронизации Chrome).
- **Изменения вёрстки сайтов** ломают селекторы правок — помечаются «не найден на странице».
