# Этап 1.5а: цвета, переменные, скроллбар — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Убрать нечитаемые элементы, найденные на живых сайтах (Facebook, Avito, Stack Overflow, Ozon, anextour, Wikipedia, Переводчик): роли переменных через цепочки и смешанные роли, Tailwind-цвета с `var()` в альфе, насыщенные фоны, `var()`-сокращения в inline-стилях, иконки-маски, лишний `scrollbar-color`.

**Architecture:** Расширяем существующий конвейер «Адаптивного» режима, не меняя его структуру. Конвейер (`src/content/pipeline`) собирает цепочки и inline-стили, индекс масок и строит зеркало с двойниками. Изображения-иконки — отдельный план 1.5б.

**Tech Stack:** TypeScript (strict), Vitest + jsdom, Playwright; без новых зависимостей.

**Spec:** `docs/superpowers/specs/2026-11-07-stage-1.5-fixes-design.md` (пункты 3.2, 3.3, 3.5, 3.7, 3.10, 3.11, 3.12; сводка в 3.9 и 3.11); основа — `2026-11-07-dark-mode-extension-design.md`.

## Global Constraints

- Manifest V3; разрешения не меняются (`storage`, `scripting`, `<all_urls>`); сети не добавляем.
- TypeScript `strict`; React 18; content script — IIFE; `zod` не попадает в `content.js` (`scripts/build.test.ts` проверяет `ZodError`).
- Префикс логов `[DarkExt]`; наши DOM-узлы — `data-darkext="placeholder|base|fallback|mirror"`.
- Ядро `src/core` — чистые функции без `chrome.*`; `src/core` ничего не импортирует из `src/ui` и `src/content`.
- Роли: `type Role = 'bg' | 'text' | 'border' | 'shadow'` (`src/core/mapping/types.ts`).
- Имя двойника переменной `--x` для роли `R`: `--x__dx-R` (`R` ∈ `bg|text|border|shadow`).
- Смешанной считается переменная, у которой доля второй по частоте роли ≥ 20 % от всех её (в том числе пришедших по цепочке) использований. Цепочки — до 5 звеньев, циклы обрываются.
- Подсказка по имени используется **только** для переменных без учтённых использований; неизвестное имя → `bg`.
- Правило насыщенных фонов (роль `bg`): цветность OKLCH > 0.10 и светлота 0.25–0.65 → цвет не меняется; светлее 0.65 → светлота 0.65 при сохранении цветности и оттенка; темнее 0.25 — не меняется.
- `scrollbar-color` и `scrollbar-width` в базовых правилах отсутствуют; `color-scheme: dark` остаётся.
- Бюджеты и защита от бесконечных перестроек из плана 1 сохраняются: перестройка не пересчитывает счётчики ролей; не более 50 переписываемых `var()` в одном значении.
- Перед каждым коммитом: `npx vitest run` и `npm run typecheck` зелёные. Модульные тесты — рядом с кодом, jsdom по комментарию `// @vitest-environment jsdom`.

## Review Focus

1. **Переменная определена в нескольких местах с разными значениями** (светлая/тёмная темы сайта: `.__fb-light-mode`, `.dark`) — двойники должны эмитироваться для каждого определения. → тест в задаче 8.
2. **`var(--x)` в месте, где двойник не определён** (определение лежит в области, которую мы не зеркалим) — запись `var(--x__dx-text, var(--x))` обязана откатываться на исходную переменную. → тест в задаче 6.
3. **Цикл `--a: var(--b); --b: var(--a)`** и очень длинные цепочки — без зависания и без бесконечных перестроек. → тест в задаче 5.
4. **Числовые и непустые не-цветовые переменные** (`--su1: clamp(...)`, размеры) — двойники и переписывание не должны ни создаваться, ни ломать значения. → тест в задаче 8.
5. **Огромное число `var()` в одном значении** (длинные `box-shadow`, градиенты) — переписывание ограничено 50 вхождениями и остаётся валидным CSS. → тест в задаче 6.

### Task 5: Таблица ролей переменных: цепочки и смешанные роли (3.10 п.1, 3.3 б)

**Files:**
- Modify: `src/core/css/vars.ts`
- Test: `src/core/css/vars.test.ts`

**Interfaces:**
- Consumes: `roleFromName` (задача 4); `roleOf(prop)` из `declarations.ts`.
- Produces:
  ```ts
  export type VarLinks = Array<[string, string]>;               // [определяемая, на_которую_ссылается]: --b: var(--a) → ['--b','--a']
  export interface VarRoles {
    roleOf(name: string): Role;          // преобладающая роль; нет использований → roleFromName(name) ?? 'bg'
    rolesOf(name: string): Role[];       // роли с использованиями, по убыванию частоты; для неизвестных — []
    isMixed(name: string): boolean;      // доля второй роли ≥ 0.2 (по эффективным счётчикам)
  }
  export function collectVarUsage(prop: string, value: string, counter: VarRoleCounter, links?: VarLinks): void;
  class VarRoleTable implements VarRoles { set(source: unknown, counts: VarRoleCounter, links?: VarLinks): Set<string>; delete(source: unknown): Set<string>; clear(): void; }
  ```
  `set`/`delete` возвращают имена, у которых изменились роль, признак смешанной или список ролей. `collectVarUsage` для `prop`, начинающегося с `--`, **не считает** использования, а добавляет в `links` пары `[prop, ссылка]` для каждой `var(--имя` в значении; для свойств с ролью — как раньше.
- Эффективные счётчики: `eff(a) = direct(a) + Σ_{d: [d,a] ∈ links} eff(d)` (глубина ≤ 5, цикл обрывается на повторном входе).
