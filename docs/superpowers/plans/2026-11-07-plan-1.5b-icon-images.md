# Этап 1.5б: тёмные значки-картинки — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Распознавать тёмные значки на прозрачном фоне (PNG, GIF, SVG, спрайты; логотипы-`<img>` с тёмным текстом) и делать их читаемыми на тёмной странице: инвертированной копией для `background-image`/`list-style-image`/`content: url()`, CSS-фильтром для `<img>`.

**Architecture:** Чистое ядро классифицирует пиксели (`classifyIcon`) и переворачивает светлоту (`invertLightness`). Service worker загружает картинки по аналогии с `FETCH_CSS` (`FETCH_IMAGE`). Скрипт на странице декодирует картинку в canvas, получает вердикт и кэширует его; зеркальные стили получают инвертированную `data:`-копию, а `<img>`-значки — атрибут `data-darkext-icon`, на который в базовых правилах действует фильтр.

**Tech Stack:** TypeScript (strict), Vitest + jsdom, Playwright, `culori` (уже есть); без новых зависимостей.

**Spec:** `docs/superpowers/specs/2026-11-07-stage-1.5-fixes-design.md` — пункты 3.1 (с поправками из 3.4 и 3.6), 3.4, 3.6; пункт 3.8 (светлые иллюстрации) **не** входит.

**Зависимость:** выполняется **после** слияния плана 1.5а в `master` (сигнатура `buildMirrorCss` получает пятый параметр поверх параметров из 1.5а). Ветка: `feat/stage-1.5b-icons` от обновлённого `master`. Атрибуция коммитов: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Global Constraints

- Manifest V3; новых разрешений нет; новых зависимостей нет; сетевые запросы — только `FETCH_IMAGE` (картинки посещаемой страницы) по образцу `FETCH_CSS`.
- `FETCH_IMAGE`: только `http:`/`https:` (адреса `data:` анализируются на странице без запроса), `credentials: 'omit'`, тип ответа `image/*`, не больше **1 МБ** (Content-Length и потоковое чтение), таймаут **10 с**, кэш LRU **100** записей; ошибки не кэшируются.
- Классификация (`classifyIcon`), вход — RGBA, уменьшенный до ≤ **64×64** с сохранением пропорций; пиксель «непрозрачный», если `alpha > 40`. Вердикт `dark-icon`, только если одновременно: прозрачных пикселей ≥ **40 %**; средняя OKLCH-светлота непрозрачных ≤ **0.35**; непрозрачных пикселей ≥ **1 %**. Критерия насыщенности **нет** (тёмный цветной текст тоже инвертируется).
- Инверсия растровой копии — переворот светлоты OKLCH (`L' = 1 − L`) с сохранением оттенка и цветности (в пределах sRGB), альфа без изменений. Для `<img>` — CSS `filter: invert(1) hue-rotate(180deg)`.
- Лимиты на странице: не более **4** одновременных анализов, не более **200** картинок на страницу; анализ асинхронный и не входит в бюджет окна загрузки.
- Анимированные GIF (> 1 кадра) **не подменяются** в CSS; для `<img>` фильтр применяется как обычно.
- Свойства CSS: `background-image`, `list-style-image`, сокращения `background` и `list-style`, `content` — только когда значение содержит ровно один `url(...)` и нет градиентов/нескольких слоёв.
- `<img>`: обе отображаемые стороны ≤ **400 px**; исходный `src` не меняется.
- Любая ошибка анализа → картинка остаётся как есть, `console.debug('[DarkExt] icon analysis failed', url)`; отключение темы снимает все наши атрибуты и копии.
- Перед каждым коммитом: `npx vitest run` и `npm run typecheck` зелёные.

## Review Focus

1. **SVG без размеров и с `currentColor`** — декодирование через `Image` должно дать размер по умолчанию, а вердикт — по реальным пикселям (чёрный `currentColor` = тёмный значок). → тест в задаче 5.
2. **Картинка недоступна / 404 / не `image/*` / больше 1 МБ** — страница остаётся прежней без исключений. → тесты задач 4 и 5.
3. **Одна и та же картинка в сотне правил или `<img>`** — один запрос и один анализ (кэш и дедупликация в полёте). → тест задачи 5.
4. **`<img>` с `srcset`/`sizes` и смена `src` скриптом** — вердикт по `currentSrc`; смена `src` снимает старый атрибут и запускает новый анализ. → тест задачи 8.
5. **Выключение темы во время анализа** — поздний результат не пишет ничего после `detach()`. → тест задачи 7.

### Task 5: Анализатор на странице (`ImageAnalyzer`)

**Files:**
- Create: `src/content/pipeline/images.ts`
- Test: `src/content/pipeline/images.test.ts`

**Interfaces:**

- Produces:
  ```ts
  export interface ImageDeps {
    fetchImage(url: string): Promise<{ dataUrl: string; animated: boolean }>;
    decode(dataUrl: string): Promise<{ width: number; height: number; pixels: Uint8ClampedArray; full: () => { width: number; height: number; pixels: Uint8ClampedArray } }>;
    encode(width: number, height: number, pixels: Uint8ClampedArray): string;      // → data:image/png
  }
  export interface IconResult { verdict: IconVerdict; inverted?: string; animated: boolean }
  export class ImageAnalyzer {
    constructor(deps: ImageDeps, opts?: { maxConcurrent?: number; maxImages?: number });
    get(url: string): IconResult | undefined;                // только готовые результаты
    request(url: string): Promise<IconResult>;               // дедупликация «в полёте»; никогда не отклоняется (ошибка → verdict 'other' + console.debug)
    onResult(cb: (url: string, r: IconResult) => void): () => void;
    dispose(): void;                                         // поздние результаты игнорируются
  }
  ```
  `decode` в браузере: `Image` из `dataUrl` → `OffscreenCanvas` (≤ 64×64 для анализа; полный размер — лениво через `full()`); для SVG без размеров — 64×64 по умолчанию. `inverted` строится только для `dark-icon` и не анимированных GIF.
